# Efficient attention over structured LaTeX papers

Give every top-level block of a LaTeX paper its own llama.cpp sequence, then
use the sequence ids as the attention mask. A question about one section can
then be answered from that section alone, and a section can be evicted or
replaced without touching the rest of the document.

The repository holds four things:

| Path | What it is |
| --- | --- |
| `latex_efficient_attention_dataset/` | LaTeX parser, JSON schema, generated dataset and parser tests |
| `driver/` | C++ driver that prefills a parsed document with structured sequence ids |
| `tests/` | End-to-end experiments against the real model, plus the batch-equivalence check |
| `results/` | Output of the last experiment run |

`llama.cpp/` and `models/` are local checkouts and are not part of this
repository.

## How it works

The parser turns each `.tex` file into a tree of nodes and, in `blocks` mode,
gives every top-level block its own `seq_id`. Each sequence owns one contiguous
range of packed positions, which is recorded in `metadata.sequence_assignment.blocks`:

```json
{ "seq_id": 4, "node_ids": ["n14"], "token_count": 261,
  "pos_min": 297, "pos_max": 557, "merged": false,
  "title": "Independent Sequences" }
```

The driver submits every token with the `seq_id` of its own block, so llama.cpp
builds the mask from the sequence ids: a token sees its own block and nothing
else. A question cannot simply join the blocks, because a sequence's positions
have to stay consecutive and the blocks end at different positions. Instead
`gather_context()` copies the wanted blocks into a dedicated scratch sequence,
and the question and its answer continue from there.

Eviction is then a single call, because a block is both one sequence and one
position range:

```cpp
llama_memory_seq_rm(llama_get_memory(ctx), 4, 297, 558);
```

## Reproducing

```powershell
# 1. Parse the documents with structured sequence ids
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe `
    latex_efficient_attention_dataset\parser\parse_latex.py `
    --output-dir latex_efficient_attention_dataset\output_blocks `
    --seq-mode blocks --max-sequences 16 --min-block-tokens 16 --xref-links

# 2. Build the driver against the existing llama.cpp build tree
cmake -S driver -B driver/build -G "Visual Studio 18 2026" -A x64
cmake --build driver/build --config Release
Copy-Item llama.cpp\build\bin\Release\*.dll driver\build\Release\

# 3. Parser tests
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe `
    latex_efficient_attention_dataset\tests\validate_output.py
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe -m unittest discover `
    -s latex_efficient_attention_dataset\tests -p "test_regression.py" -v

# 4. End-to-end experiments (slow: it runs the model for every document)
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe tests\run_experiments.py

# 5. Foundation check: a batch equals separate runs
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe `
    tests\test_batch_equivalence.py

# 6. Cross-references and small-block merging, which the corpus never triggers
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe `
    tests\test_fixture_paths.py

# 7. Rebuild the slide and the audit from the last run
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe tests\make_slide.py
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe tests\write_audit.py
```

## What gets asked, where

`results/test_audit.txt` is the full record: every question, prompt, prefill,
eviction target and answer, grouped by test. It is generated by
`tests/write_audit.py` from the test modules and the last experiment run, so
it cannot drift from either. Regenerate it after any run.

## Reports

| File | What it answers |
| --- | --- |
| `results/slide.md` | the one-slide summary: domain, tree statistics, test results, CPU run times |
| `results/test_audit.txt` | every prompt, question, prefill, eviction and answer, by test |
| `results/mask_construction_notes.txt` | how a sequence id becomes an attention mask, with line references into llama.cpp |
| `results/run_experiments.txt` | the raw console output of the last experiment run |
| `results/batch_equivalence.txt` | the raw output of the batch-equivalence test |
| `results/experiments.json` | the same results, machine readable |
| `results/project_0_slide.pdf` | a comprehensive slide |

All of them are generated, never hand-edited, so they cannot drift from the
code:

* `test_audit.txt` reads the questions and focus blocks out of the test modules
  and the answers out of `experiments.json`, and it **runs the parser suites to
  measure the test counts** rather than quoting remembered numbers. It also
  refuses to write if a document's block ranges do not tile its positions.
* `slide.md` recomputes the tree statistics from the parser output on every
  run, so they track the current dataset rather than the run that produced the
  numbers.
* The answer budget lives in one place, `run_experiments.py:N_PREDICT`, and
  both reports quote it from there.

Regenerate the lot with:

```powershell
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe tests\make_slide.py
.\latex_efficient_attention_dataset\.venv\Scripts\python.exe tests\write_audit.py
```

## Driver modes

```
--mode stats         print the tree and sequence layout, run nothing
--mode prefill       load the document into the KV cache, generate nothing
--mode ask           ask a question and generate greedily
--mode evict         prefill, evict one block, ask again
--mode replace       prefill, evict one block, refill it, ask again
--mode two-prompts   run two prompts as two independent sequences
                     (omit --prompt-b for a single-prompt reference run)
```

Useful options: `--focus-seq <n>` answers from one block only, `--evict-seq <n>`
picks the block to remove, `--replace-file <file>` supplies replacement text,
`--logits-out <file>` writes a per-step top-logit trace, `--no-follow-xrefs`
stops the driver gathering the blocks a block cites, and `--offset-a <n>` places
prompt A for the reference run. `--help` lists them all.

## Two things worth knowing about the measurements

**Text equality is not a sufficient test on CPU.** Removing KV cells changes
the attention reduction order, so a greedy choice can flip even when the
context is provably identical. The experiments therefore compare the top logit
at every generated step. A different context moves it by whole units; float
noise moves it by hundredths. `tests/run_experiments.py` also runs a positive
control, evicting the subtree the answer actually comes from, because without
it the isolation results would pass trivially.

**Isolations are compared single threaded.** `run_experiments.py` takes
`--isolation-threads` (default 1) for the comparisons and `--threads` (default
8) for the timings. At one thread the logits are bit-identical when the context
is the same, which makes the result a statement about masking rather than about
floating point.
