PART 0 - Constants used by the tests
==============================================================================

Model settings inside the driver
  sampler chain     : top_k -> top_p -> temp -> greedy
  greedy            : the last sampler in the chain decides, so a run
                      is reproducible given the same context
  kv_unified        : true for the document modes, because
                      gather_context() copies whole blocks with
                      llama_memory_seq_cp(), which needs one buffer
  question placement: the focused blocks are copied into a scratch
                      sequence (the highest seq_id) and the question
                      and its answer continue from there, because a
                      sequence's positions must stay consecutive

Questions per document (tests/run_experiments.py:QUESTIONS)
  document_1_transformer_architecture        'What does the attention mechanism compare?'
  document_2_kv_cache_management             'What does the cache store for each token?'
  document_3_mathematical_results            'What does the paper illustrate?'
  document_4_structured_documents            'What do research papers contain?'
  document_5_attention_masks                 'What does an attention mask determine?'

Focused block per document (tests/run_experiments.py:FOCUS)
  the block the question is answered from

  document_2_kv_cache_management             1
  document_3_mathematical_results            1

  document_5_attention_masks                 1

Block changed per document
  the largest block that is not the focused one, so the eviction
  is as visible as possible:

  document_2_kv_cache_management             9
  document_3_mathematical_results            4
  document_4_structured_documents            9
  document_5_attention_masks                 9

Replacement text (driver/replacement_subtree_b.txt)
      Positions during prefill are assigned by the runtime, not by the
      caller. The driver reads them from the parser output and submits them
      unchanged, so a subtree can be replaced at the same position range it
      originally occupied.

Prompts (tests/test_batch_equivalence.py:PROMPTS)
  'Hello my name is'
  'The capital of France is'

Generated tokens
  The document experiments pass -n 24 (run_experiments.py:N_PREDICT),
  so every answer stops after that many tokens and often ends
  mid-sentence.  That is the budget, not a fault: an answer does
  not have to be a finished sentence to be provably unchanged, and
  a fixed budget keeps the before/after comparison the same length
  for every document.  Raise it there to read longer answers.

content-loss audit, theorem classification, math rendering and the

PART 7 - Batch equivalence (no document)
==============================================================================

Two prompts in two sequences of one context must give exactly what
the same prompts give one at a time.

Prompts, as they are actually submitted:
  'Hello my name is'
  'The capital of France is'

Sequence 0 gets prompt A at positions 0.. and sequence 1 gets prompt B
past the end of sequence 0.  A KV cell is addressed by position, so
two prompts both starting at zero would overwrite each other.

Commands:
  # the batched run
  llama-latex-driver --mode two-prompts \
      --prompt-a 'Hello my name is' --prompt-b 'The capital of France is' -n 16 -t 1

  # the reference run for prompt A, on its own
  llama-latex-driver --mode two-prompts --prompt-a 'Hello my name is' \
      --offset-a 0 -n 16 -t 1

  # the reference run for prompt B, at the offset it held in the batch
  llama-latex-driver --mode two-prompts --prompt-a 'The capital of France is' \
      --offset-a <stride> -n 16 -t 1

  # the upstream example, for the independence property
  llama-batched -m <model> -p 'Hello my name is' -n 16 -np 2 -t 1 --kv-unified


Recorded run (results/batch_equivalence.txt):
  === llama-batched, one prompt shared by two sequences ===
    (the upstream example samples stochastically, so this section changes on every run; only the independence property is being checked here, not the exact text)
    seq 0 -> "Hello my name is Samantha I'm a 30 year old married and a"
    seq 1 -> "Hello my name is Aisha, I'm a huge fan of the movie"
    the two sequences diverge, so they are independent
  
  === driver two-prompts, two different prompts ===
    seq 0 prompt 'Hello my name is'
      batched -> ' Emily and I am a huge fan of your work. I recently came across your'
      single  -> ' Emily and I am a huge fan of your work. I recently came across your'
    seq 1 prompt 'The capital of France is'
      batched -> ' Paris. The capital of France is Paris. The capital of France is Paris.'
      single  -> ' Paris. The capital of France is Paris. The capital of France is Paris.'
    seq 0: MATCH
    seq 1: MATCH
  
  === one prefill batch instead of two ===
    seq 0 separate -> ' Emily and I am a huge fan of your work. I recently came across your'
    seq 0 joint    -> ' Emily and I am a huge fan of your work. I recently came across your'
    max logit shift between the two prefill splits: 0.2699
    a joint prefill moves the logits by more than 0.25, so the split of the prefill is part of the comparison, not the mask
  
  every batched run matched the corresponding separate runs
